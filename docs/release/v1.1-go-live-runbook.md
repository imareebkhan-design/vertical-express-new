# Version 1.1 Go-Live Runbook

This runbook outlines the deployment sequence for deploying Vertical Express Version 1.1 to the production environment.

## 1. Pre-Deployment Checks
1. Verify production environment variables are fully configured.
2. Confirm the Sentry and PostHog API keys are set.
3. Check PostgreSQL connection pooling and load limits.

---

## 2. Deployment Sequence

### Step 1: Database Migration
Deploy database schema changes using Prisma migrations:
```bash
npx prisma migrate deploy
```
> [!IMPORTANT]
> Never use `prisma db push` on a production database. The deploy command executes all pending migrations (including the pg_trgm extension creation and payments indexes) sequentially.

### Step 2: Vercel Production Build & Release
Trigger Vercel build and deployment:
```bash
vercel --prod
```
Vercel executes the `vercel-build` command defined in `package.json`:
`prisma generate && prisma migrate deploy && next build`

### Step 3: Webhook Configuration
Verify that the production Razorpay webhook URL points to:
`https://verticalexpress.com/api/webhooks/razorpay`

> [!WARNING]
> Do NOT execute the database seed command (`npm run db:seed` or `tsx prisma/seed.ts`) against the production database. The seed script is designed for development and test initialization, and running it in production will overwrite active product catalog prices and inventory records. If production lookup or config data changes are needed, they must be executed via custom, controlled schema/data scripts, not the standard seed file.

---

## 3. Post-Launch Monitoring
1. Monitor Sentry dashboard for any unhandled React or Prisma exceptions.
2. Verify active connection pools on the Supabase console.
3. Confirm that health metrics return `{"status":"healthy"}` at `/api/health`.
