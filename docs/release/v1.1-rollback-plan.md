# Version 1.1 Rollback Plan

This document details rollback procedures in case of critical production failures post-launch.

## 1. Application Rollback (Vercel)
If a critical server exception occurs on the frontend/API:
1. Navigate to Vercel deployments dashboard.
2. Locate the previous release candidate build (Version 1.0 baseline).
3. Click "Promote to Production".
4. Vercel routes all client traffic to the safe version in under 2 seconds.

---

## 2. Database Rollback
Prisma migrations for Version 1.1 are backward-compatible (adding indexes, columns, and new tables without deleting or renaming old schemas).
If a rollback is required:
1. Revert schema definitions in `schema.prisma`.
2. Do NOT run destructive SQL rollbacks unless data is corrupted.
3. If database restore is needed, trigger Supabase Point-in-Time Recovery (PITR) to restore state to the pre-deployment timestamp.

---

## 3. Payment Rollback
If the payment gateway (Razorpay) exhibits high latencies or API failures:
1. The gateway configuration can be toggled by updating `PAYMENT_GATEWAY` environment variable.
2. Changing `PAYMENT_GATEWAY` to `dummy` in staging/development or configuring fallbacks protects the platform during outage windows.
